# SVSVDAC Temple — Online Pooja Booking

React JS + Vite frontend using PrimeReact and PrimeFlex, with an Express API, Prisma ORM and TiDB Cloud (MySQL-compatible). The Render blueprint provisions an API web service and a static frontend service.

## Features
- English / Telugu UI toggle
- Pooja catalog and devotee booking form
- Gotram, family member names, mobile, email, address and preferred date/time
- Booking reference and devotee booking lookup
- Admin login, booking status management, pooja creation/editing
- TiDB Cloud database via Prisma

## Local development
Requirements: Node.js 20+ and a TiDB Cloud database (or compatible MySQL database).

1. Copy `server/.env.example` to `server/.env`, and set `DATABASE_URL`, a strong `JWT_SECRET`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD`.
2. Copy `client/.env.example` to `client/.env`.
3. In `server/`: `npm install`, then `npx prisma db push`, then `npm run db:seed`, then `npm run dev`.
4. In `client/`: `npm install`, then `npm run dev`.
5. Open http://localhost:5173. Admin page: `/admin/login`.

## Render deployment
1. Push this folder to a GitHub repository.
2. In Render choose **New + → Blueprint**, select the repository and use `render.yaml`.
3. Set `DATABASE_URL` to the TiDB Cloud connection string, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `CLIENT_URL` to the deployed frontend URL on the API service. `JWT_SECRET` can be generated by Render.
4. The static service's `VITE_API_URL` is wired to the API service's `RENDER_EXTERNAL_URL` by the blueprint. If Render does not resolve the service reference in your workspace, set it manually to the API's `https://...onrender.com` URL.
5. After deploy, run database setup against the production database from a trusted local terminal: in `server/`, set production `DATABASE_URL`, then run `npx prisma db push` and `npm run db:seed`. Do not expose database credentials in the frontend.
6. Update the API's `CLIENT_URL` to the exact static site origin and redeploy the API.

## Vercel alternative
Deploy `client/` as a Vite static site on Vercel with `VITE_API_URL` set to the Render API URL. Deploy `server/` separately on Render. Configure the API `CLIENT_URL` with the Vercel domain.

## Important configuration
- Configure TiDB Cloud TLS/SSL according to the connection details provided by TiDB. Keep the connection string only in the server environment.
- Seeded pooja names/prices are sample values. Confirm actual services and amounts with the temple before accepting bookings.
- UPI is currently an instruction-based/manual payment flow. No payment is collected or verified by this starter app. Add the temple's verified UPI ID and reconciliation process before launch.
- Booking submissions are requests with `Pending` status; an admin must confirm them. Availability slots are not capacity-reserved in this starter.
- Admin session uses an HTTP-only cookie and JWT. Use HTTPS in production and a strong secret/password.
- Review privacy notice, retention, access controls, backups, and local legal requirements before collecting real devotee data.
